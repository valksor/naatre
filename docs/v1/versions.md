# Documentation version tuple

These guides describe specification `1`, schema profile `core.schema-1`, canonicalization `c14n-1`, fixture suite `1.0.0`, profile registry `1.0.0`, and the Go reference runtime development component `0.0.0-development.1` built with Go 1.27. The exact machine-readable tuple is [evidence.json](evidence.json); normative fixture versions are [suite.json](../../conformance/v1/suite.json) and [profiles.json](../../conformance/v1/profiles.json).

There is no published stable runtime or SDK release matching this checkout. All SDKs are an unpublished development snapshot and have independent component/profile/runtime identifiers in their fixture files: [Go](../../conformance/v1/go-sdk.json), [JavaScript/TypeScript](../../conformance/v1/typescript-sdk.json), [PHP](../../conformance/v1/php-sdk.json), [Python](../../conformance/v1/python-sdk.json), [Rust](../../conformance/v1/rust-sdk.json), [JVM](../../conformance/v1/jvm-sdk.json), [.NET](../../conformance/v1/dotnet-sdk.json), [Swift](../../conformance/v1/swift-sdk.json), [Dart](../../conformance/v1/dart-sdk.json), and [Ruby](../../conformance/v1/ruby-sdk.json). A source checkout or passing test does not turn that snapshot into a release.

A published documentation version must name an immutable release manifest that pins specification, schema model, canonicalization, fixtures, conformance suite, runtime, generators, every SDK/worker, source revisions, artifact digests, support rows, and reports. The current [example manifest](../../releases/example.manifest.json) is deliberately draft and makes no release claim.
