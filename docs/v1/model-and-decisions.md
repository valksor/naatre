# Language model and architecture decisions

Naatre documents are language-neutral JSON. A document has ordered operations/fragments and each operation has an ordered selection array. Arrays are ordered because declaration order determines response ordering, sequential mutation behavior, pipeline flow, deterministic parallel error ordering, alias collision detection, and semantic hashes. JSON object member order is semantically unordered because objects represent named records/maps; canonicalization sorts their keys by UTF-16 code units. Reordering a selection array changes meaning, while reordering object members does not.

The type system separates input from output positions and presence from nullability. Core scalars are Boolean, String, ID, Int32, and Float64; extended Int64, UInt64, BigInt, Decimal, Timestamp, Duration, UUID, and Bytes use the exact string forms in [schema](../../spec/v1/schema.md) and [scalar fixtures](../../conformance/v1/scalars.json). Lists, string-keyed maps, objects, enums, open tagged unions, interfaces, and one-of inputs retain their declared shapes. JavaScript-safe numeric JSON is limited to -9007199254740991 through 9007199254740991; wider integers and decimals are strings and must never pass through binary64.

Missing means a key was absent. Null means a present key carried JSON null. Optional/non-null may be missing but not null; required/nullable must be present but may be null. Selected output also has pending, failed, and skipped states. Timestamp offsets are explicit; comparison uses instants, canonical output normalizes as specified, and applications must not silently apply a machine-local time zone. Strings are valid Unicode scalar sequences and canonicalization does not normalize equivalent compositions; UTF-16 sorting is for canonical object keys, while byte limits count UTF-8 where the clause says so.

The architecture decisions are explicit registration rather than reflection; separate missing and null; safe structured errors with stable code, clause/source/path, and simultaneous partial data; transport-independent language/runtime cores; purpose-domain-separated SHA-256 over canonical JSON; declared entity type/key/service identity; explicit stream open/frame/end state with bounded replay and source ownership; and generated SDKs derived from a versioned language-neutral model. Transports, frameworks, adapters, workers, and native runtimes earn separate support evidence.

Compatibility changes follow [the evolution policy](../governance/releases.md): independently versioned components, editorial/compatible/deprecated/breaking classification, stable deprecation windows, executable migration guidance, immutable release manifests, and conformance evidence. Unknown open enum/union variants are preserved where the profile allows them; unknown language tags, closed types, extensions, or required capabilities fail closed.
