# Third-party implementation guide

Choose one bounded profile, not “all of Naatre.” Pin the spec, schema, canonicalization, fixture suite, profile registry, generator model, and external references. Implement strict JSON decoding first: duplicate keys after unescaping, invalid Unicode, unknown members/tags, trailing data, and budget exhaustion must fail at the specified phase. Preserve ordered arrays, semantically unordered object members, missing/null, safe integers, time-zone offsets, Unicode scalar validity, and canonical UTF-16 key ordering.

Build immutable schema and handler registries with explicit registration. Keep decode, validate, plan, authorize, execute, complete, and serialize separate; no business handler runs before full validation and planning authorization. Add deny-by-default dynamic authorization, finite request/process budgets, panic/exception containment, safe error redaction, truthful mutation effect states, and owned cancellation/cleanup before adding optimizers, transports, federation, or workers.

Consume fixtures directly and publish a `naatre.conformance.report-1` report binding implementation version, source revision, platform/runtime, profile, fixture digests, passes, failures, and explicit unsupported capabilities. Mark support planned until source exists, implemented only when the component profile executes, and tested only for exact passing report rows. A remote worker behind the Go gateway is a remote-worker implementation, not a native runtime.

For SDKs, generate from the language-neutral model, preserve open variants and selected states, make cancellation strength explicit, bound transports and queues, strip credentials on untrusted redirects, and never replay a mutation automatically. For a native runtime, independently implement planning, authorization, execution, completion, resource accounting, error ordering, streaming ownership, and conformance; wrapping or delegating those phases to the Go gateway does not qualify.

Start with [core fixtures](../../conformance/v1/core.json), [language](../../conformance/v1/language.json), [schema/value/scalars](../../conformance/v1/schema.json), [canonicalization](../../conformance/v1/canonical.json), [security](../../conformance/v1/security.json), and [profiles](../../conformance/v1/profiles.json). Then add only the fixtures named by the claimed profile. Follow [release governance](../governance/releases.md), publish source/decision provenance, and use the [troubleshooting workflow](troubleshooting.md) for every public code.
