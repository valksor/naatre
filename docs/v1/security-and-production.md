# Security and production deployment

Production admission starts deny by default. Configure `runtime.AuthorizationDenyByDefault`; install a planning authorizer for static rejection and a dynamic authorizer for each selected handler occurrence; authenticate transport credentials into a trusted principal context; authorize again at remote service boundaries; and keep unregistered fields, calls, methods, operations, schemas, endpoints, origins, redirects, extensions, adapters, and persisted documents unreachable. The executable reference is [authorization_conformance_test.go](../../runtime/authorization_conformance_test.go), and the normative rules are [SEC-100 through SEC-405](../../spec/v1/security.md).

Set finite non-zero bounds before readiness for compressed and decompressed input bytes, decoder tokens/depth/members, string/number/array sizes, validation errors, regular-expression work, schema recursion, plan depth/nodes/calls/selected fields/static cost, queue and parallel width, collection expansion, retries, output completion, serialized response bytes, public errors, active requests, per-tenant and per-principal partitions, streams, worker connections, replay, file transfer, process drain, cleanup, and connection lifetime. Use [HTTP defaults](../../transport/http/handler.go) only as a starting ceiling, then lower them for the application. Invalid configuration must prevent readiness.

Redact credentials, tokens, variables, handler causes, stack traces, database/provider messages, protected identifiers, tenant/principal values, cursor internals, worker topology, and policy reasons from responses, metrics, traces, logs, cache keys, and health. Map unknown application failures to `INTERNAL`. Keep detailed causes only in access-controlled private diagnostics joined by an opaque correlation identifier.

Terminate TLS and workload identity in an operator-owned ingress, restrict exact origins and credential forwarding, pin schema/profile/release revisions, disable automatic mutation replay, use persisted allowlists where feasible, supervise all processes, and drain admission before rotating connections or revisions. A cancellation signal is cooperative: an in-process handler, remote mutation, blocking PHP/Python backend, or external provider may continue. Retain accounting and ownership until it actually exits or durable handoff is proven.

Threats covered by the v1 defaults include introspection/reflection exposure, confused-deputy delegation, authorization bypass through caches/batches/federation, request and decompression bombs, deep/alias/parallel cost amplification, Unicode and duplicate-key ambiguity, unsafe numeric coercion, cursor/replay probing, SSRF and credential-forwarding redirects, worker impersonation/schema drift, error exfiltration, persisted-hash confusion, partial-result zero-value injection, and cancellation-driven replacement loops. Trusted in-process callbacks are not a sandbox; hostile code needs process isolation.
